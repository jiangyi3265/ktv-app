# 1.0.9 小程序微信通知连接修复

## 原因与修复

收到用户已授权的反馈后，服务器仍没有管理员绑定或订阅提交记录。进一步检查 1.0.8 正式小程序产物，发现编译时没有传入 `VITE_KTV_API_ORIGIN`，导致请求使用 `/ktv-api/...` 相对地址。H5 可使用本站反向代理，而微信原生请求需要完整 HTTPS 地址；因此 H5、后端及模拟交互通过，并不能证明该小程序包已经连接服务。

此前验收遗漏了正式小程序产物的地址核对。1.0.8 关于三端真实连接的结论应以本记录更正，不能把授权未登记单纯归因于用户没有操作。

1.0.9 已将正式地址 `https://chang.uuok.top` 编译进小程序。后端业务、电脑后台、通知模板与用户绑定均保持现有配置，没有替用户增加订阅次数。

## 防止重复发生

- 小程序开发及构建入口必须读取并验证 `VITE_KTV_API_ORIGIN`；缺省、相对地址、HTTP、账号密码、路径/查询参数以及本机/IP 地址均拒绝。
- 编译结束后加载实际 `common/api.js` 产物，核对通知状态、订阅提交和上传三个最终 URL 及认证头。校验失败时构建返回失败，不能把普通编译完成当作可发布。
- 微信开发者工具交互测试先检查编译后的 HTTPS URL，再安装模拟业务接口，避免模拟覆盖掉地址问题。
- 生产地址属于公开配置，不把 AppSecret、Token 或账号密码写入小程序。

## 验证

- 客户端 36 项测试通过；没有配置地址时构建明确失败。
- 对旧 1.0.8 编译产物运行新增校验，确认会失败；对 1.0.9 产物运行同一校验通过。
- 微信开发者工具开启域名检查，直接使用编译后的 API 模块和真实 `wx.request` 连接线上：真实微信登录换取顾客会话、PC 管理员登录、备货账号登录、订单状态读取及三角色通知模板状态读取均成功。验证后撤销仅本轮创建的登录会话。
- 上述真实接口验证未模拟网络、未修改微信绑定、未发起测试通知、未创建营业订单或支付退款。
- 构建产物 508 个文件与复制后的上传目录一致，未发现已知实际凭据。
- 三角色模拟授权交互回归通过，H5 构建通过；H5 沿用相对 API 与原有代理逻辑，本次不用重发后端或电脑后台。

## 构建命令

PowerShell：

```powershell
$env:VITE_KTV_API_ORIGIN='https://chang.uuok.top'
npm run build:mp-weixin
```

也可以在被忽略的本地环境文件配置该变量。部署其他小程序时替换成对应的已登记 HTTPS 域名，并核对该小程序的合法域名配置。

## 本人操作与验收边界

需在微信公众平台将 1.0.9 设为体验版，再重新打开小程序。管理员、备货人员分别进入对应工作台，先连接微信，再点击授权并允许；以「已授权，预计还可接收 N 条」及服务器状态为准。一次性订阅每次授权仅提供一次发送机会，不能由服务端代替授权。

真实消息送达仍需要本人授权后，使用正常业务订单验证管理员和备货方各自收信。实际请求验证、模拟授权或发送接口返回成功，都不能等同于手机已收到、响铃或已读。
