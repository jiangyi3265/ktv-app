# 1.0.7 会话隔离复查

本轮重点检查顾客、食堂及移动管理页面在慢请求、登录失效、退出与账号切换时的数据归属。已修复可复现的会话竞态，并部署 H5、上传微信开发版本 1.0.7；手机体验版仍需在公众平台手动切换。

## 发现与修复

- 登录失效后，早先发出的成功查询可能把订单界面重新恢复为可操作状态；现在失效立即清空账号、订单详情、统计与列表，并拒绝旧响应。
- 退出账号等待服务器响应期间仍可看到旧业务数据；现在先清除本地会话，迟到的退出回执也不能把顾客页面切回食堂。
- 离开登录页后，迟到的成功登录结果会改变当前角色；现在只接收当前页面、当前登录尝试的结果，废弃会话会尝试注销。
- 旧筛选请求的失败、旧订单详情和旧 token 的失效响应可能影响新页面；现在同时核对角色、会话、请求序号、筛选、分页和订单。
- 被替换的顾客初始化可能写回旧身份或恢复凭据；现在写入前检查当前上下文。
- 保存后切换账号，旧操作可能刷新新页面、释放新操作的等待锁，或在保存后的刷新完成时继续导航；现在保存回执和后续刷新均检查账号上下文。跨账号结果提示回原账号核对，避免把不确定状态当成未保存而重复操作。

## 可重复运行

```bash
npm test
npm run test:session-browser
```

浏览器测试支持 `KTV_TEST_APP_ORIGIN`（H5 地址）、`KTV_TEST_OUTPUT`（报告目录）、`PLAYWRIGHT_MODULE`（已安装 Playwright 的模块路径）。所有 KTV 业务请求均由测试模拟，不读取真实账号密码。

跨端写入回归 `npm run test:shared-browser`、`npm run test:shared-resilience`、`npm run test:supplier-lifecycle` 需要隔离后端及专用凭据，禁止对营业环境运行。环境变量和已有流程说明见 [1.0.6 复查记录](2026-11-13-订单同步复查.md)。
