# 1.0.6 订单同步复查

## 修复内容

- 备货人员接单后按返回，原先可能看到缓存的“待接单”详情。订单步骤切换现在替换当前页面，返回可直接回到工作台。
- 其他设备更新订单时，隐藏的缓存页面原先可能将当前工作台跳转到配送页面。现在只有可见详情页能同步路由，打开旧链接则显示订单的实际步骤。
- 订单进入退款中、已退款或取消状态时，停止显示备货、出餐与送达按钮，关闭未提交的确认弹窗，并显示停止配送提示；服务端状态校验仍为最终依据。
- H5 快速切换页面时，UniApp 图片加载回调可能在元素卸载后触发 `appendChild` 异常。餐品图片及图标在 H5 使用浏览器原生 `img`，保持尺寸和裁切方式；微信小程序保留原生 `image`。

## 可重复运行的回归

先启动隔离后端和 H5，设置以下环境变量：

- `KTV_TEST_API_ORIGIN`：隔离后端地址。
- `KTV_TEST_APP_ORIGIN`：隔离 H5 地址。
- `KTV_TEST_ACCESS`：仓库外测试账号 JSON 路径，结构包含 `admin`、`supplier`，各有 `username`、`password`。
- `PLAYWRIGHT_MODULE`：可选，已安装 Playwright 的绝对路径。
- `KTV_TEST_OUTPUT`：可选，截图和报告输出目录；默认 `.local/supplier-lifecycle`。

运行 `npm run test:supplier-lifecycle`。脚本在创建订单前要求后端开启隔离环境模拟付款；不要对营业环境运行。订单流转使用真实测试接口，退款展示单独模拟，不修改付款配置。脚本结束会关闭浏览器。

## 线上检查与待验收项

H5 修复版已部署；410 个文件与本地构建摘要一致，后端程序及电脑后台文件与上一版本一致。微信开发版本 1.0.6 已成功上传，包体约 1.5 MB；手机端需在公众平台将此版本设为体验版后再检查。

线上只读检查确认后端健康、真实微信支付/登录已配置、模拟付款关闭、通知模板启用，备货账号不能读取管理员通知配置。

检查时备货账号尚未连接微信、订阅余额为零，因此离开小程序后的实际提醒尚未完成验收。需由备货人员在体验版工作台完成“连接微信提醒 → 授权接收微信提醒”，随后以实际业务订单验证收到通知；一次性订阅用完后需要重新授权。发送成功也不代表对方已读。

手机真实付款、退款到账与实际微信消息送达不在本次模拟和隔离测试的通过范围内。
