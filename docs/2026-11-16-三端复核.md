## 回归脚本修正

`tests/shared-resilience.cjs` 原先在菜单加载后立即检查包厢文字，没有等待独立扫码解析请求；保存权限也未明确等待保存响应，可能将尚未完成的界面操作判成失败。现在等待包厢文字解析完成、权限开关状态更新及对应 PUT 响应，并核对 HTTP 200 后再检查其他账号权限。修正后原脚本复测通过，不将早期失败运行计为通过。

测试准备时修正了隔离 API 对新 PC 预览端口的来源配置，并恢复意外退出的本地预览服务。线上服务未受这些本地测试环境调整影响。

## 尚需本人完成的营业验收

复查时管理员 `admin` 尚未绑定微信，备货账号 `A01` 已绑定但可用次数为 0。两人需在小程序对应角色页面连接微信、允许订阅；一次授权仅提供一条消息的发送机会，次数用尽需再次授权。

授权完成后，用正常业务订单确认管理员与备货人员实际收信，以及顾客收到接单/配送通知。服务器发送成功不等于手机响铃或已读。

真实退款仅在明确允许退款的营业订单上验收：申请、微信处理、顾客状态、账单冲减及到账均需核对。本轮使用隔离样本和模拟退款状态验证代码，没有对真实已付款订单退款。

测试证据保存在被 Git 忽略的 `.local/final-check-*` 和 `qa/` 中；不将生产凭据、OpenID 或营业订单明细提交到仓库。
