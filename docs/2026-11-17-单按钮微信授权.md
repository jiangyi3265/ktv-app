# 1.0.13：三端单按钮微信授权

顾客订单页、商家管理与食堂接单工作台共用 `StaffNotifications`。原先需要先连接微信，再点击授权；现在点击「开启微信提醒」，在微信原生弹窗中允许后，程序自动登录微信、绑定当前业务账号并保存订阅结果。

## 行为与异常处理

- 微信订阅接口直接在按钮事件中调用，网络请求放在用户允许之后，避免异步请求丢失用户点击触发条件。
- 服务器确认保存后才显示成功和剩余提醒次数。拒绝、禁止订阅、连接失败、保存失败都有明确反馈。
- 保存时模板已改变，必须重新取得该模板的授权。页面销毁或切换账号后丢弃旧操作，不把授权记到新账号。
- 一次性模板每次授权只增加一次提醒；保留刷新、再次授权和关闭提醒入口。微信原生授权弹窗仍由用户本人确认。
- 电脑后台「接单通知」的扫码说明同步更新。

## 验证

- 单元测试 40 项通过。
- 微信开发者工具 12 项检查通过：三种角色单按钮授权、拒绝、禁止订阅、绑定失败、失败重试、保存失败、模板变更、账号切换、取消提醒及正式 HTTPS 请求地址。
- 原生检查模拟了微信授权和业务传输，没有向真实用户发送测试通知，也不代表手机实收已验收。
- 浏览器检查使用真实线上接口，验证电脑后台通知配置、管理员和食堂登录、服务首页与返回入口、关闭点餐后的页面跳转，以及 320/390/430 宽度；没有更改营业设置。
- 三端源码与前端产物经过敏感信息检查。H5、电脑后台和微信构建通过；发布核对 699 个网页文件与 512 个小程序文件。

## 持续通知边界

本次实时查询微信接口：当前商家/食堂与顾客模板均为一次性模板（type 2）。当前所属类目的公共库返回 723 项，其中 type 2 为 519 项、type 4 为 204 项，没有返回 type 3 长期模板。未将未确认含义的 type 4 当作长期模板使用。

用户要求在普通微信持续收新单，目前只有该小程序账号。本次没有新增服务号或企业微信群通道，也没有伪造长期订阅权限。持续接收每单提醒尚未实现；需要先取得适用业务场景的官方持续通知能力。微信一次性授权次数与“保持以上选择”的说明参见[腾讯云官方文档](https://cloud.tencent.com/document/product/1301/103770)。

## 发布

H5 与电脑后台部署到 `20261117-one-tap-notices-1.0.13`；后端 JAR、数据库及营业开关不变。微信开发版本 1.0.13 上传成功（1,551,141 字节），需管理员在微信公众平台将其设为体验版。真实手机授权、微信通知到达仍需用户配合确认。
